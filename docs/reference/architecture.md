# Architecture

File-by-file map of the codebase. For the patterns that span these files (save queues, hot paths, watchdogs, etc.) see [patterns.md](patterns.md).

## macOS target (Miniti)

- **Miniti/MinitiApp.swift** – App entry point, force update gate, onboarding gate, menu bar, global keyboard shortcuts, custom URL callback handling (Attio and Twenty OAuth returns), and centralized `openOrRestoreMainWindow()` handling for Dock, menu, notification, and floating-panel actions. Only visible, miniaturized, or app-hidden identified windows count as restorable; an X-closed SwiftUI window can linger briefly in `NSApp.windows` and must fall through to `openWindow(id:)` scene recreation.
- **Miniti/Models/AppState.swift** – Central `@MainActor` state: recording, transcript, insights, audio monitoring, app mode, usage tracking, transport/audio recovery state, managed session-end durability queue, save queue, Live Activity lifecycle (`#if os(iOS)` guarded), and Google Calendar state. High-frequency signals are split into `AudioLevelsState` and `TranscriptRuntimeState`. `HomeSetupState` separately owns persisted setup presentation and cached permission evidence; guide/footer/Settings subtrees observe it without invalidating history. macOS dual-channel finals use Deepgram word times on a reconnect-aware meeting timeline, a bounded channel-ordering buffer, deterministic equal-time tie-breaks, and chronological insertion for mic speech released late by echo reconciliation. Final transcripts drain through the serialized save queue before slower AI work moves into meeting-scoped background tasks tracked by `finalizingInsightMeetingIDs`, allowing a new live session without cross-meeting writes. `salesInsightsEnabled`, `templateInsightsEnabled`, and `playbookInsightsEnabled` persist specialist-view opt-ins and gate Sales generation / Template generation / Playbook availability; `insightTemplateID` is the default built-in template for new meetings and `liveTemplateID`/`liveTemplateSections` hold the live meeting's own; configuring a valid Docs MCP enables Playbook. `defaultLanguage` stores the global language and `meetingLanguage` the current meeting language. Calendar settings control connect, auto-start/stop, and independent Attio/Twenty company-domain sync; upcoming events span future days, locally stored prep notes are keyed by calendar event ID and seed the live meeting notes, and `startMeetingFromEvent(_:)` pre-fills title, event ID, attendees, and prepared notes. A bounded local transcript heuristic owns investigation suggestions without making an AI request; an explicit click runs a meeting-scoped OpenAI request, with web citations or bounded, symlink-free, likely-secret-redacted security-scoped code excerpts on macOS, and meeting/request identity guards discard stale results. `SettingsGroup` and `SettingsDestination` (the settings registry, legacy id mapping, and `SettingsSearchCatalog`) live here too. `privateModeEnabled` with `setPrivateMode` (snapshot and restore of the nine settings it forces, `PrivateModeRestore`) controls cloud AI preferences and guards; the running-session lock and History/Watch consent guards shipped in 3.4.0; the wider AI-entry-point audit remains deferred in [reliability](../plans/reliability.md); `rememberedSpecialistMode` is the More tab's memory for the meeting.
- **Miniti/Models/Meeting.swift** – SwiftData model for persisted meetings. `isPinned` supports stable priority in grouped history and `insightsUpdatedAt` records visible insight freshness. Includes `managedSessionId: String?` to persist the backend session ID across app kills for orphaned-session usage reporting. `language: String` (default `"en"`) stores the meeting's transcription language. Optional `externalSource`, `externalID`, `externalURL`, and `importedAt` fields preserve import provenance and support source-scoped duplicate detection; `provenanceDisplayName` supplies the user-facing source label. `calendarEventId: String?` links to the originating Google Calendar event. `attendeesJSON: String?` stores meeting attendees as JSON; decoded via computed `attendees: [MeetingAttendee]` property. `suggestedQuestionsJSON: String?` stores AI-generated questions as JSON; decoded via computed `suggestedQuestions: [SuggestedQuestion]` property. `speakerNamesJSON: String?` stores inferred speaker ID → real name map as JSON; decoded via computed `speakerNames: [String: String]` property (setter filters out empty values and clears the JSON when the map is empty). `speakerOverridesJSON: String?` stores the set of speaker IDs whose name was set manually by the user. `setSpeakerName(id:name:)` is the single entry point for user-driven edits. `displayTitle` strips legacy timestamp prefixes and is used by all display/export surfaces.
- **Miniti/Views/MinitiDesignSystem.swift** – Shared visual contracts compiled into macOS and iOS: spacing, radii, compact-control metrics, motion, opacity states, semantic control roles, content accents, lowercase navigation copy, neutral tab primitives, and shared card surfaces. Presentation components deliberately leave behaviour with their enclosing native controls.
- **Miniti/Services/AudioCaptureService.swift** – Mic (AVAudioEngine) + system audio (Core Audio Process Tap) capture, publishes separate levels, auto-recovers system tap on silent-stall and callback-stall through a capture-scoped watchdog that also covers system-only recording, and retries failed tap restarts with bounded backoff. `suspendSending()`/`resumeSending()` implement the ending-grace send gate: captured audio is dropped before any sample accounting (levels keep metering, tap callbacks keep firing) so the Deepgram sample clock and source log pause together; the silent-stall detector and post-recovery escalation stand down while suspended.
- **Miniti/Services/CallActivityMonitor.swift** – macOS-only Core Audio process-object monitor for call-app lifecycle detection. Polls `kAudioHardwarePropertyProcessObjectList` + `kAudioProcessPropertyIsRunningInput` once per second off the main actor, excludes Miniti's own PID and bundle prefix, normalizes helper bundle IDs through `CallApplicationDirectory`, and emits immutable `CallActivitySnapshot`s to AppState. Uses only public HAL properties — no camera, Accessibility, screen contents, or private API. Started/stopped with the Smart meetings setting and paused across system sleep.
- **Miniti/Models/CallLifecyclePolicy.swift** – Shared (macOS+iOS-compiled) pure call-lifecycle policy: snapshot/confidence types, the known-app/helper normalization directory (browsers are app-level only and carry a distinct `browser` confidence), `EndingGraceState`, and the deterministic `CallLifecycleEngine` (start debounce/prompt suppression, association formation rules, end debounce with transcript-quiet veto, reactivation cancel, transition candidates, and the expected-call window that lets a join-style start adopt the call that appears instead of offering a transition). Covered by `MinitiTests/CallLifecycleTests.swift` in both bundles.
- **Miniti/Views/RecordingIndicatorPanel.swift** – macOS-only floating call/recording surface: non-activating borderless `NSPanel` owned by `RecordingIndicatorCoordinator` (position persistence + full-frame screen clamping, all-Spaces/full-screen-auxiliary), plus the shared `AppState.RecordingPresence` presentation model used by both the panel and menu bar. It appears for recording and every Smart-meeting prompt, auto-expands and explicitly reorders front for new start/end/transition/quiet/calendar decisions, recording start, ending grace, and foreground question/coaching nudges, then stays hidden while idle. Its full-width header carries an explicit AppKit drag handle (`RecordingIndicatorDragHandle`): drags past the disclosure tolerance move the window with `performDrag(with:)`, clicks toggle expansion, so moving the window never changes expansion and the header no longer depends on `isMovableByWindowBackground` reaching through SwiftUI (broken on macOS 27). Foreground nudges expire without mutating recording state; every decision action routes through the same AppState methods as the main window. Visibility follows the independent default-on `showRecordingIndicator` setting, while `MacNotificationRoutingPolicy` sends the equivalent system notification when another app is active or the surface is disabled.
- **Miniti/Views/AcknowledgementsView.swift** – Shared `AcknowledgementsSection` for Settings → About: one disclosure per third-party notice, text loaded on open from `Miniti/Resources/Acknowledgements` (FluidAudio Apache 2.0 plus its component notices, the Nemotron-3-Diarization notice, the Nemotron-3.5-ASR notice for the speech model downloaded on request, the OpenMDW 1.1 agreement both NVIDIA models ship under, Sparkle on macOS). Add a file there and an `Acknowledgements.Entry` when a dependency is added; `AcknowledgementsTests` fails if a listed file is missing from the bundle
- **Miniti/Services/OnDeviceDiarizationService.swift** – On-device speaker diarization (NVIDIA Nemotron-3 via the FluidAudio Core ML port, `low` preset, 1.04 s latency). `OnDeviceSpeakerTimeline` is a lock-protected per-source array of dominant speaker per 10 ms frame; `markSocketStart()` pins each Deepgram socket's time 0 to the diarizer clock so socket-relative word timestamps map onto it. The service loads the bundled models for each capture source, runs one `Nemotron3Diarizer` per source on a serial queue fed by the same PCM16 the app sends to Deepgram (`splitPCM16` de-interleaves dual capture), and hands the timeline to `DeepgramService.connect(onDeviceSpeakerTimeline:)`. Cloud recordings retain Deepgram separation when local preparation is unavailable before start. Local 3.7.0 mid-session failures instead invalidate the timeline and voice evidence and show unavailable separation; lag preserves ready models, while load/inference failures require retry. Stop uses the backlog-aware bound in [local models](local-models.md)
- **Miniti/Services/OnDeviceTranscriptionService.swift** – On-device live transcription (NVIDIA Nemotron 3.5 ASR Streaming Multilingual 0.6B via FluidAudio, Core ML int8, 1120 ms chunks; 2.12.0, default off, macOS setting). `OnDeviceTranscriptionSupport` maps miniti languages to model language codes, families (`latin` for en/es/fr/de/pt/it, `multilingual` for nl/ru) and tiers (tested, experimental, cloud-only for el/pl/sv); `OnDeviceTranscriptionCopy` builds the setting text from those tiers. The service downloads and preloads one `SharedNemotronMultilingualModels` per family into Application Support/FluidAudio/Models (on demand, about 590 or 640 MB) and hands `Session`s to `DeepgramService.connectLocal`: one `StreamingNemotronMultilingualAsrManager` per capture source with personal dictionary and calendar keyterms as vocabulary biasing, a worker task per source draining an `AsyncStream` of samples, and a `LocalUtteranceAssembler` that groups token timings into words (on the SentencePiece `▁` marker) and utterances (sentence punctuation, 1 s silence at the decoded horizon, 12 s cap), emitting interims and finals. `DeepgramService.makeLocalResponse` shapes each event as a `DeepgramResponse` (channel index by source in dual capture, no provider speaker) and `processTranscriptResponse`, the body shared with the JSON path, runs it through the same speaker mapping, identity allocation, and segmentation. While a session is local there is no socket task, so `sendAudio` cannot upload; `gracefulDisconnect` finishes the session and waits for the last final. `AppState.willTranscribeOnDevice` decides the engine once per start (`sessionTranscribesOnDevice`), managed mode opens no Deepgram `/api/session`; released 3.7.0 separately queues enrolled managed local/private duration without consuming Deepgram allowance, BYOK needs no Deepgram key, and `onDeviceTranscriptionBlocksStart` refuses a start when the model is not ready unless the per-meeting Deepgram fallback setting is on
- **Miniti/Services/DeepgramService.swift** – WebSocket streaming transcription (Nova-3 only), ordered off-main JSON decode + speaker segmentation with reconnect-generation stale-result guards, `TranscriptionLanguage` enum with 11 supported languages and per-language default filler lists, `configure(credential:authorizationScheme:)` for managed `Bearer` JWTs vs BYOK `Token` API keys, explicit `TranscriptSource` attribution (multichannel by `channel_index`, mono by capture topology) with `SpeakerIdentityState` mapping per-channel provider speaker numbers to collision-free app speaker IDs (mic → `1000 + n`, generation-aware across reconnects), confidence-aware speaker-change gating/new-speaker promotion, and connection-health signals for reconnect orchestration. With an `OnDeviceSpeakerTimeline` the `/v1/listen` query omits `diarize_model` (`makeListenQueryItems`), each word's provider speaker and confidence come from the timeline (`providerSpeaker(...)`), and `SpeakerIdentityState` keys those sources at generation 0 so reconnects keep every app ID
- **Miniti/Services/DocsMCPService.swift** – BYOK Streamable HTTP MCP client for docs search (`tools/list` / `tools/call`), search-tool discovery, Mintlify-style chunk normalization, and SSRF URL validation. Shared by macOS + iOS.
- **Miniti/Services/GranolaCSVImporter.swift** – Shared Granola migration service. Reads the zip Granola emails (stored or deflated CSV entries, several parts; `GranolaZipReader` in the same file) or CSV files off the main actor, tolerates header variants (a `document_`/`note_`/`meeting_` prefix is stripped when the bare name is known) and multiline quoted fields, maps summary (markdown flattened to plain text), notes, and transcript into `Meeting`, and skips source IDs imported before. Today's bulk export has no speakers, timings, end time or attendees: unlabelled transcripts are joined per sentence into turns of one unnamed speaker, the length is estimated at 150 words a minute, and turn timestamps follow word position. Lines that mostly carry `Name:` keep their speakers. Plan: `docs/archive/granola-import-plan.md`.
- **Miniti/Services/InsightsService.swift** – OpenAI API for summaries, action items, MEDDPICC, suggested questions, Docs topic extraction, and per-topic grounding. `InsightsMode` keeps stable raw/API values while exposing user-facing Summary / Sales / Coaching / Questions / Playbook / Template labels plus core/specialist groupings. Template requests send the `InsightTemplate` definition (and, after the first fill, the current sections as a stability baseline) and parse `sections` back through `InsightTemplateSections.normalize`. `CoachingAdvisor` owns local cross-meeting ranges, trend analysis, and the positive/negative/neutral interpretation used by stats arrows. Language-aware prompts respond in the meeting language. Questions has a dedicated conversational-gap prompt; coaching filler preferences and metrics are per-language; speaker-name inference uses transcript evidence with optional calendar hints.
- **Miniti/Services/WebhookService.swift** – Outbound webhook on meeting save. `validate(_:)` is the single transport rule (https with a host, or http to loopback only) used by Settings and `send`; `redactedEndpoint` (scheme + host) is all that ever reaches logs. The durable outbox posts `meeting.saved` after the saved transcript and final processing settle, independently of going Home or cloud sync; later saved changes enqueue update events. Payload includes title, start/end dates, duration, language, summary, action items, key decisions, topics, discussion flow, notes, MEDDPICC, Coaching metrics under the backward-compatible `training` field (per-speaker fillers, pace, talk ratio, monologue, questions, clarity), suggested questions (array of `{question, type, context}`), speaker count, `speaker_names` (speaker ID → inferred real name map, only sent when non-empty), full transcript (array of `{speaker, text, timestamp}` entries with human-readable speaker labels already resolved against the inferred names), and optionally `calendar_event_id` and `attendees` (array of `{email, name, domain}`). The active outbox calls `deliver` with a 15-second attempt timeout, stable delivery-ID/attempt headers and bounded retries within 24 hours. The legacy detached `send` helper is not the durable delivery path. Two payload builders: one from live AppState data, one from a persisted `Meeting` model. `trainingData(from:)` converts `TrainingMetrics` to the webhook-friendly `TrainingData` struct. Works with Zapier, Make, n8n, and custom endpoints. Shared between macOS and iOS.
- **Miniti/Services/DebugLogger.swift** – In-memory ring-buffer logger (1000 entries) with API key redaction. Thread-safe `log()` callable from audio threads. Categories: audio, deepgram, app. Lines stay in the buffer (and the in-app debug log / export) — nothing is mirrored to stdout or `os_log`. Shared between macOS and iOS.
- **Miniti/Views/DebugLogView.swift** – Terminal-style log viewer with category filters, pretty/raw modes, copy, and clear. Raw mode supports direct text selection for partial copy. Accessed via hidden 5-tap on version text in Settings.
- **Miniti/Services/KeyboardShortcutsService.swift** – Global keyboard handler for recording, navigation, Catch me up, pane collapse, search, and the help overlay. Insight-view number shortcuts were removed because the visible set is customizable.
- **Miniti/Services/DeviceIdentifier.swift** – Keychain-based persistent device UUID (survives reinstalls). Access is serialized because several independent integrations can resolve the ID concurrently, and successful resolution is cached in memory so routine API calls do not repeatedly cross into Security.framework; UI-triggered callers such as CRM sheets still resolve it off-main. If Keychain persistence is temporarily unavailable (for example iOS test-host / entitlement failures like `status=-34018`), the app reuses a `UserDefaults` fallback ID instead of generating a fresh UUID each call; with no fallback, a read status other than `errSecItemNotFound` yields a session-only ID that is never written (`DeviceIdentifier.resolution(afterReadStatus:hasFallback:)`), so an unreadable item can never be replaced by a new identity. That keeps managed usage, Google Calendar, Attio, and Twenty linkage stable. If this fallback ever shows up on real devices, add stronger diagnostics/telemetry rather than silently ignoring it. Storage goes through `KeychainSlot` (same file, shared with `KeychainClientAuthStore`): data protection keychain where the build can use it, login keychain on macOS otherwise, updated in place, nothing deleted until the replacement exists; `KeychainBackend` is the Security.framework seam the tests fake. `DeviceIdentifier.adopt(_:reason:)` lets `ClientAuthManager` restore the id named by the stored access token (the 3.2.1 regression, `docs/reference/distribution.md`).
- **Miniti/Services/MinitiAPIService.swift** – Backend communication (`classifySalesConversation` / `classifySpeakerNames` call the managed Jev proxy `POST /api/classify`; a 503 `classifier_unavailable` maps to `ServiceError.classifierUnavailable` so `AppState` falls back to GPT or the phrase heuristic) (also hosts `CalendarMeetingFilterPreferences` / `CalendarMeetingSkipReason` and `CalendarEvent.skipReason(under:)`, the adjustable meeting-filter rules; `UsageInfo.isProViaAccount` for account-sponsored Pro): usage checks, managed Deepgram grant-token sessions (`SessionResponse` prefers `access_token` over deprecated `temp_api_key`; requires `expires_at` or `expires_in`), insights proxy, version checking, Apple subscription verification, Attio/Twenty CRM export helpers, and Google Calendar integration (connect/status/events/disconnect). Managed requests use device-bound bearer authorization and an ES256 `X-Request-Proof` on writes through `ClientAuthManager`; legacy identity/version/platform headers remain for compatibility. There is no shared `X-API-Key` secret in the app. The unauthenticated version check remains available before enrollment. CRM calls use explicit bounded request timeouts (status 10s, connect/search 15s, send 30s), and `CRMTaskPayload` carries the previewed task content/deadline list independently from the complete meeting-note action items. `checkVersion()` sends `X-Device-ID` and `X-App-Mode`, but the route never creates device records. It touches an existing record only when an accompanying credential validates; unauthenticated BYOK checks are not enrollment. Handles 403 `device_disabled` — sets `isDeviceDisabled` on AppState to block recording and show user message. Session-end decoding supports backend idempotency diagnostics. `generateInsights()` sends optional `language` field (defaults to `"en"`) and optional `attendees` array for context enrichment. Google Calendar types: `CalendarEvent`, `CalendarAttendee`, `CalendarOrganizer` with convenience properties (`startDate`, `endDate`, `externalAttendees`, `attendeeDomains`). `CalendarAttendee.toMeetingAttendee()` converts API types to persistable `MeetingAttendee`. Server-side limits, enrollment admission and device-bound proofs remain complementary controls; do not reintroduce a shared app secret. See [accounts](accounts.md).
- **UpdateService.swift** (repo root, not `Miniti/Services/`) – Sparkle 2 integration. Singleton `UpdateService.shared` owns `SPUStandardUpdaterController`. File is guarded by `#if os(macOS) && canImport(Sparkle)` so the app still builds if the SPM dep is ever missing. Wired into `MinitiApp.swift` via `CommandGroup(after: .appInfo) { Button("Check for Updates…") { UpdateService.shared.checkForUpdates() } }`.
- **Miniti/Views/MeetingView.swift** – Main meeting UI: ReadyStateView (home) with animated `FlashingTagline`, `MeetingLanguagePicker`, active session, audio source panel, waveforms, and `CalendarNudgeCard` (when Google Calendar isn't connected and the nudge isn't dismissed). Home lists the next five calendar events across coming days and opens an event-preparation sheet before starting one. Recording shows a local investigation-suggestion banner and explicit in-app OpenAI web/codebase actions; the result sheet renders answers, clickable web citations, and reviewed code-file names. The header also shows a language badge for non-English meetings.
- **Miniti/Views/MainWindow.swift** – Window chrome, neutral Home / Coaching / History sidebar, browser-style destination history, and macOS historical meeting detail (`MeetingDetailView`, includes `send to attio` and `send to twenty` sheets). A shared provider-backed CRM sheet owns OAuth connect, scoped search, record selection, meeting-note export, and optional action-item tasks; its task preview shows deadline/assignee/link metadata and owns the per-task selection sent to the backend, while provider wrappers retain distinct callback schemes, notifications, colors, deadline policies, and preferences. Deliberate dominant two-finger horizontal trackpad gestures move back/forward between Home, Coaching, and visited meetings without consuming ordinary scroll events; a neutral edge dial follows eligible gestures and fills at the commit threshold. Coaching overview rows open meeting detail and provide an explicit return to Coaching. CRM sheet setup keeps Keychain work off-main, uses the shared semantic controls and neutral tabs, and cannot send while disconnected. History search debounces the query briefly before recomputing results, which reduces UI churn on larger datasets.
- **Miniti/Views/TranscriptView.swift** – Shared live transcript state and rendering; merges streaming fragments into sentence-level turns, incrementally rebuilds the finalized tail, computes bounded whole-paragraph mutations for rare chronological middle insertions on macOS, uses selectable lazy rows on iOS, and hands the attributed document to the macOS native pane
- **Miniti/Views/LiveTranscriptTextPaneMac.swift** – macOS-only native TextKit 2 live transcript scroller; owns one selectable `NSTextView`, applies finalized/interim tail mutations in place, preserves stable selections, follows the bottom without animation, and distinguishes user live scrolling from layout/programmatic movement
- **Miniti/Services/ClientAuth.swift** – Device-bound authorization for managed mode. `ManagedEnrollmentCoordinator` (3.4.0) holds the migrate-then-create policy `AppState.ensureManagedEnrollment` delegates to, testable without a host; `ClientAuthManager` reports `ClientAuthEvent`s (rotation, conflict, unreadable or undecodable credential, failed draft write, silent re-create) through a sink `AppState` attaches, with a bounded buffer for launch-time events. Also: `ClientAuthCrypto` (base64url, SHA-256, RFC 7638 thumbprints, Crockford recovery keys with checksum, request targets), `InstallationKey` (Secure Enclave or software P-256, ES256 compact-JWS challenge and request proofs), `ClientAuthCredentials` in a this-device-only Keychain item, and `ClientAuthManager` (create / restore / silent legacy migrate, refresh-then-challenge token grants with a shared in-flight gate, server-clock skew correction, device list, rotate, sign out, delete). `MinitiAPIService.send(_:)` is the only caller for normal traffic; `/version` goes out unauthenticated before enrollment.
- **Miniti/Services/CloudSyncEngine.swift** – Cloud sync (3.0.0): `CloudSyncEngine` (`@MainActor`, owned by `AppState`) keeps finished, non-excluded meetings equal to the account's cloud copy through a `CloudSyncHost` (what it needs from the app) and a `CloudSyncTransport` (the routes). Dirty detection is `MeetingSyncDocument.fingerprint` against the fingerprint the cloud last saw; pushes are one `PUT` per meeting with the server revision as base and last-writer-wins on `updated_at` (server tombstones and the trim guard always win); pulls walk `/api/sync/changes` from a per-account cursor in `UserDefaults` and fall back to a manifest reconcile on `cursor_expired` or first enable. `CloudSyncPause` names every reason it is not running. Protects active/final-transcript work from uploads, permits a durable stopped meeting to upload while selected, and separately protects selected/final-AI meetings from incoming replacement. See [cloud sync](cloud-sync.md).
- **Miniti/Services/MeetingSyncDocument.swift** – The wire form of a meeting (schema_version 1, contract in `../miniti-api/docs/agents/08-cloud.md`): `encode` (lowercase ids, ISO 8601, JSON columns passed through as JSON, unknown fields from another client echoed from `Meeting.syncExtraJSON`), `decode`/`apply`/`makeMeeting` (segments replaced only when the transcript revision moved), and the cheap `fingerprint`.
- **Miniti/Services/MinitiAPIService+Cloud.swift** – `CloudSyncTransport` conformance for `MinitiAPIService` plus the Settings → Cloud management calls (tokens, email, connected apps). Documents travel as raw JSON data so the request proof covers the exact bytes.
- **Miniti/Models/AppState+CloudSync.swift** – `AppState: CloudSyncHost`: the pause reason (`cloudSyncEnabled`, managed, enrolled, private mode off, Pro), commits through `commit(.cloudSync)`, History reload and macOS auto-export after pulls, `setCloudSyncEnabled`, per-meeting `setMeetingExcludedFromCloud`, `deleteCloudCopy`. Account events (sign out, move, delete) call `cloudSync.resetBookkeeping()`. Also the account email (B6a, 2026-10-27): `AccountEmail { verified, pending }`, `AccountEmailState`, `accessCardVisible`, `refreshAccountEmail` (coalesced, 60 s freshness, generation plus sequence ordering), `addAccountEmail`, `removeAccountEmail`, the browser-callback and activation observers, and `accountEmailMessage(for:)`.
- **Miniti/Models/MeetingTombstone.swift** – `@Model` written in the same save as a user delete when the meeting had a cloud copy (`noteMeetingDeleted(_:createTombstone:)`), sent as `DELETE /api/sync/meetings/{id}`, removed on acknowledgement.
- **Miniti/Views/CloudSettingsView.swift** – Settings → Cloud on both platforms (`CloudSettingsSections`, macOS wrapper `CloudSettingsView`, `CloudEnableSheet`, `CloudSyncLogView`, `MCPSetupRows`): switch, status with View log, web sign-in email, connected apps, API tokens shown once with copy-and-paste MCP snippets per tool, delete cloud copy. Observes the engine directly. `EmailSignInSheet` (in `ManagedAccountViews.swift`) is the new-device join: send a link, poll `/api/auth/email/status`, then `AppState.joinAccount(approvedLinkID:)` (attach when enrolled, restore when not).
- **Miniti/Views/ManagedAccountViews.swift** – The recovery-key sheet, the sign-in and switch sheet (`RestoreRecoveryKeySheet(mode:)`), `AccountSectionModel` (the eight account states as data: email line and actions, recovery key line and actions, key notes, hidden versus disabled actions, plan and restore wording), the Home `AccountAccessCard` (B6a), the Settings, Account section (Your account, Ways to sign in, Devices, then sign out and delete), and the shared Settings → Calendar → Meeting filters section (`CalendarMeetingFiltersSection`), all shared by macOS and iOS.
- **Miniti/Services/InsightTemplates.swift** – The built-in `InsightTemplate` catalog (BANT, SPIN, interview scorecard, customer check-in, stand-up, 1:1) with the section-count/length limits mirrored from the backend, `InsightTemplateSections` (normalize/encode/decode/markdown helpers shared by every export surface), and `InsightTemplatePrompt`, the BYOK prompt that mirrors the backend's `buildTemplatePrompt`. Change both prompts together.
- **Miniti/Views/TemplateSettingsViews.swift** – Settings → Templates: the built-in and custom template lists and `InsightTemplateEditorSheet`. The editor opens with a "Describe it" field whose Draft it button calls `AppState.draftInsightTemplate(from:)` (managed `/api/insights` mode `template_draft`, or BYOK `InsightsService.draftInsightTemplate` with the same prompt) and fills the `InsightTemplateDraft`; fields are label-above, left-aligned, with counters only near a limit
- **Miniti/Views/InsightsView.swift** – AI insights panel with persistent neutral lowercase summary / questions / coaching tabs and a More menu for opt-in Sales, built-in and custom Templates (in the flat More menu), and Playbook specialist views; `InsightTemplateMenu`, `InsightTemplateCaption`, and `InsightTemplateSectionList` are the shared template pieces used by all four renderers. Owns the Coaching overview, whose lowercase focus / stats / history tabs separate personalized trends, a wider six-metric comparison table with one-line label-side units, visible row explanations and semantic arrows, six per-metric chart cards with independent y-scales and adaptive meeting-sequence x-axes, and the sortable meeting table, plus shared coaching detail, question-card, Docs topic/card, citation, and metric-help UI. Coaching trend sections use one restrained reading column on every platform, desktop-only enlarged typography, content-driven heights, untruncated copy, and hoverable source cards that keep label/quote together at left while the right-aligned meeting title sits above date-only metadata. The More tab (`InsightsModeTabs` on macOS, `InsightsModeTabs_iOS`) is one flat menu, Sales with the templates then Playbook, names only, and remembers the specialist chosen for the meeting: a click on the tab returns to it (`Menu(primaryAction:)`), the indicator opens the menu. In private mode the tab, the investigate and catch-up buttons, and the saved-meeting update button hide and `PrivateModeInsightsNotice` replaces cloud content.
  - Since 3.9.0 `CoachingOverviewStore` caches computed Coaching rows in `Application Support/Miniti/Coaching/rows-v1.json` (titles, metrics and the short transcript excerpts used as examples). Keyed by meeting signature, discarded on every app build, pruned when meetings are deleted, never used by tests or screenshot mode. Rows are analysed four at a time at utility priority.
- **Miniti/Views/SettingsView.swift** – Resizable macOS settings window with a fixed, non-collapsible sidebar, in-sidebar search, `Command-F`, persisted destination, setting-level result breadcrumbs, and direct form scrolling. ## Shared vs platform-specific files

**Target membership:** `Miniti.xcodeproj/project.pbxproj` is authoritative. Models and most services/views under `Miniti/` are shared; platform-specific entry points, capture services and shells are not. `Shared/RecordingActivityAttributes.swift` belongs to the iOS app and Live Activity extension; `Shared/WatchRecordingProtocol.swift` joins the watch and receiving apps. Do not infer membership from a source folder alone.

**macOS-only files**: `MinitiApp.swift`, `AudioCaptureService.swift`, `KeyboardShortcutsService.swift`, `MainWindow.swift`, `MeetingView.swift`, `LiveTranscriptTextPaneMac.swift`, `SettingsView.swift`, `UpdateService.swift`

**Key design**: Keep platform guards (`#if os()`) limited and localized. Most platform-specific branching lives in `AppState.swift` (ActivityKit + source-dominance wiring), with additional targeted guards in shared UI/service code where platform behavior differs (for example `DebugLogView`, `InsightsView`, `MinitiAPIService`, and macOS-only CRM UI in `MainWindow`). Each target compiles its own `AudioCaptureService` (same class name, same public interface). AppState references `AudioCaptureService` by name and works with either version. Shared views use `@Environment(\.horizontalSizeClass)` for responsive layout. MEDDPICC fields and Template sections are rendered as individual sections (same heading style as summary/discussion) across all views — `LiveInsightSection` in the sidebar, `TerminalSection` in full-width/history, `DetailInsightBlock` in saved detail, `InsightsPlainBlock_iOS`/`HistoricalDetailBlock_iOS` on iOS. Template sections take `ColorPalette.Templates` colors in template order so the same section is the same color on every surface.

**Critical wiring**: `appState.modelContext` must be set from `@Environment(\.modelContext)` in the first view that appears. On macOS this happens in `MainWindow.swift`; on iOS in `MainTabView.swift`. Without it, fire-and-forget saves log and no-op, while the revision-fenced `saveCurrentMeetingAndWait()` reports failure. `MinitiApp.swift` owns the macOS terminate-later fence; `MinitiApp_iOS.swift` owns the UIKit background-task lease.

**macOS SwiftData stability note (v1.9.0)**: `MainWindow.swift` intentionally avoids a root-level `@Query` for history and stores `selectedMeetingID` (UUID) instead of a `Meeting` object in `@State`. Meetings are fetched manually from `ModelContext` (including on app reactivation) to avoid a SwiftUI/SwiftData crash path seen when clicking the window after it had been backgrounded. `MeetingDetailView` uses `.id(meeting.id)` so SwiftUI fully tears down the old view (including `@Bindable` observation tokens and gesture recognizers) before creating a new one when switching meetings — without this, stale AttributeGraph references cause `EXC_BAD_ACCESS` in the button gesture dispatch path.
