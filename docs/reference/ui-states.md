## Current limitations and private-mode semantics

Configured webhook/CRM exports remain allowed in private mode. In 3.4.0, `setPrivateMode` refuses while starting, recording, resuming or finalizing and the Privacy overview reports the latched route. - **Deepgram and OpenAI permission** (first launch, or after a disclosure change): names both companies, says what each receives, offers "allow" and "not now". Not now opens the app with recording and AI features off and nothing sent; tapping record shows the same screen as a sheet; Settings, Privacy shows the choice and changes it. Backed by versioned storage in `@AppStorage` (`acceptedTermsVersion`, `declinedTermsVersion`, legacy bool migration).
- **Onboarding** (first launch, after terms): Responsive two-step flow. Miniti Free is the primary path, BYOK is secondary, then a real microphone meter lets the user verify permission and input before continuing or deferring setup.
- **Home** (`ReadyStateView`): Mode-aware — managed shows usage status, BYOK shows API pills; animated "multi-dimensional meetings" tagline; audio source panel and a concise capture-source/language summary; cog button (top-right) opens settings. The primary Start meeting action always begins a fresh unscheduled meeting. The upcoming list shows the next five connected-calendar events across coming days; selecting one opens a preparation sheet where private notes can be added or edited before starting, and those notes seed the meeting's live notes. `CalendarNudgeCard` renders above the start button when Google Calendar isn't connected and the nudge hasn't been dismissed.
- **Home (limit reached)**: In managed mode when the effective allowance is exhausted (500 free / 5,000 Pro minutes) — inline "switch to BYOK" prompt, start button disabled
- **Home (device disabled)**: In managed mode when admin has disabled the device — shows "account disabled" message, start button hidden
- **Starting**: Spinner with "starting..." text while waiting for managed mode key or audio setup — stays on home screen until recording begins
- **Recording**: TerminalHeader with red dot + timer, stop button, dual labeled waveforms (mic green, system blue), transcript, notes, live insights. A bounded local heuristic can surface a dismissible investigation suggestion without making an AI call; the user can explicitly run in-app OpenAI web research or a Mac codebase investigation, and a proper shared-style header button opens the same two-choice popover at any time. The result sheet leads with the answer, keeps web citations visible and clickable, lists code files actually reviewed, supports refresh, and cancels cleanly on dismissal. With default-on Smart meetings, an amber prompt can ask whether quiet means the meeting ended or whether to end and start an approaching calendar event; calendar prompts offer End & start next, Keep recording, and Remind in 2 min, while quiet prompts offer End meeting and Keep recording. On macOS every pending start/end/quiet/calendar choice also expands and raises the non-activating floating recording surface, and optional incisive-question/monologue/filler guidance uses that surface while Miniti is frontmost. Notification Center is the fallback when attention is in another app or the surface is disabled; the same decisions remain in the menu bar. On macOS, finalized and interim content share one native scrolling TextKit 2 document: users can select across speaker turns, finalized selections survive incremental tail updates, and the view avoids the per-row SwiftUI selection overlays that could enter a multi-gigabyte layout loop during window resizing. ### Saved Mac selection during text-size changes

Changing InterfaceScale rebuilds attributed transcript text. When the characters are unchanged, the native macOS renderer preserves its selected range through that rebuild, including full-document mutation and ordinary attributed-input paths. Character edits retain the existing TextKit/trim selection policy. The native measurement layer retains at most four width/height results for unchanged attributed text and invalidates them on every applied edit or style change. See the [saved-screen evidence](../releases/3.9.0.md#saved-mac-screen-performance-and-selection); programmatic resizing and scrolling do not close physical pointer, Settings or whole-screen accessibility gates.
