## Confirmed opportunities

### F09.1 Make each Docs topic lifecycle a discriminated value

- **Owner / verdict:** S09 — recommend.
- **Evidence:** `DocTopic` stores `lookupState`, `card?`, and `errorMessage?` independently (`Miniti/Services/InsightsService.swift:116-165`). The live and saved paths manually coordinate those fields in two nearly identical switches (`Miniti/Models/AppState.swift:3263-3292`, `3311-3333`), while the UI must guard state and payload again (`Miniti/Views/InsightsView.swift:982-1029`, `1036-1092`). Tests can construct `.answered` without a card or `.failed` without a message because the initializer accepts all combinations (`Miniti/Services/InsightsService.swift:140-151`).
- **Current complexity / invalid states:** Seven nominal states combine with two optionals into many invalid/stale combinations. `.answered + nil`, `.pending + error`, and `.noMatch + card` are representable. Busy deliberately may retain a prior card, but that relationship is implicit and duplicated transition code can drift.
- **Proposed representation:** Replace the three fields with a Codable/Equatable `Resolution` enum carrying required payloads: `.pending`, `.lookingUp`, `.answered(card)`, `.noMatch`, `.busy(message, cachedCard?)`, `.failed(message)` (retain a cached card only in cases where the UI actually presents it). Expose computed `card`/display helpers if needed. Put one pure `applying(outcome)` transition on the value and use it for live/history containers.
- **Smallest credible scope:** `DocTopic`/legacy decoding in `InsightsService.swift`, live/history transitions in `AppState.swift`, Docs row rendering, JSON round-trip/model tests. Do not redesign MCP transport or quota policy.
- **Risks / migration:** `docTopicsJSON` persists across versions, so custom decoding must accept the legacy `{lookupState,card,errorMessage}` shape and encode the new representation compatibly or through a staged migration. Preserve busy-with-prior-answer behavior, topic identity/dedup, no-match retry and quota handling.
- **Validation:** Extend `InsightsParsingTests.swift:327-356` with every legal state, rejection/normalization of legacy contradictions, old/new JSON round trips and pure transition tests; retain `MeetingModelTests.swift:785-803`. Later run both bundles/builds and manually exercise managed/BYOK auto/manual lookup, success/no-match/busy/failure/quota, retry, persistence/relaunch, history lookup, webhook/export and deletion in flight.
- **Confidence:** medium.
- **Roadmap status:** new. Roadmap P0.10's backend acceptance verification is a separate handoff.

### F03.1 Derive unsaved-session state from the save queue's durable fingerprint

- **Owner / verdict:** S03 — recommend; release-data priority.
- **Evidence:** `hasUnsavedSession` is an independently mutable Boolean (`Miniti/Models/AppState.swift:534-535`), set true only at meeting creation/restore (`:4431`, `5103`) and false after a latest matching save (`:5380-5392`). Subsequent transcript changes advance `liveTranscriptRevision` without re-setting it (`:4053-4069`). The existing fingerprint covers meeting identity/metadata, transcript revision, insights, notes, Docs and speaker state (`:5276-5315`). macOS termination skips its save fence when the Boolean is false (`Miniti/MinitiApp.swift:68-78`). Existing durability tests do not cover re-dirtying after a checkpoint (`MinitiTests/AppStateComputationTests.swift:1743-1809`).
- **Current complexity / invalid states:** The save queue already owns requested/successful revisions and state fingerprints, while a second Boolean summarizes durability and can contradict them. Sequence: successful periodic save → later finalized text/notes/insight mutation → Command-Q can return `.terminateNow` despite newer state.
- **Proposed representation:** Retain the last successfully committed fingerprint per meeting and derive read-only `hasUnsavedSession` as current persistable fingerprint != durable fingerprint or latest requested revision > successful revision. Use the existing queue representation; do not introduce another state machine.
- **Smallest credible scope:** `AppState.swift`, with `AppDelegate` retaining the same read interface, plus dirtiness tests. No SwiftData schema migration.
- **Risks / migration:** Fingerprint must cover every save payload field and is only an in-process comparison; associate it with the correct meeting. Avoid delaying termination for meetings with no persistable finalized content. Preserve deletion durability, A→B coalescing and the five-second macOS fail-open.
- **Validation:** Add save→mutate transcript/notes/title/speaker→dirty, older-commit/newer-state-stays-dirty, latest-commit-cleans, A→B and deletion-in-flight tests. Later run both bundles/builds; record BBC audio past a checkpoint, add speech, Command-Q/background, relaunch and verify the tail, plus prior-store/interrupted-session upgrades.
- **Confidence:** high.
- **Roadmap status:** not named as this defect, but directly affects P0.4 abrupt-termination durability and corrects its assumption about current normal-termination behavior.

### F03.2 Give store bootstrap one shared owner and explicit failure state

- **Owner / verdict:** S03 — recommend; known/planned.
- **Evidence:** Both roots duplicate schema/config creation and crash on open failure (`Miniti/MinitiApp.swift:187-199`; `MinitiMobile/MinitiApp_iOS.swift:76-88`). `AppState.modelContext` remains optional (`Miniti/Models/AppState.swift:533-535`), then feature views install it after appearance (`Miniti/Views/MainWindow.swift:447-452`; `MinitiMobile/Views/MainTabView.swift:33-40`). Save handles absence as a log/failure (`AppState.swift:5417-5422`), and tests normalize this invalid state as expected behavior (`MinitiTests/AppStateComputationTests.swift:1793-1809`).
- **Current complexity / invalid states:** Container creation, context activation and recovery are owned by three layers; persistence-capable session state can exist without a context, and store-open failure is representable only as process termination. Root gates incidentally delay context wiring.
- **Proposed representation:** One shared `MeetingStoreBootstrap`/`MeetingStore` with `.ready(container, mainContext)` and `.failed(contentFreeFailure)`. Both roots use the same schema/config factory; a root host installs context in AppState once, independent of main feature views, and renders recovery without deleting/recreating the store.
- **Smallest credible scope:** One cross-platform source file, both app roots, an explicit AppState context-install interface, removal of context wiring from `MainWindow`/`MainTabView`, focused startup tests. Preserve store URL/schema.
- **Risks / migration:** Never create two containers/contexts, change store location/container identity, auto-reset a failed store, or isolate macOS Settings on another container. Keep preview/test in-memory injection and lightweight migrations.
- **Validation:** Add normal/failure/retry/root-gate/same-store tests. Later run both bundles/builds and manually test normal launch, populated-store upgrade, interrupted recovery, Settings/history access, deliberately unopenable/corrupt store recovery, sandboxed notarized DMG upgrade and iOS archive/install upgrade.
- **Confidence:** high.
- **Roadmap status:** explicitly planned by P0.2 and overlapping P0.3; this finding narrows them to one store/bootstrap ownership boundary.

### F02.1 Represent the post-finalization command once

- **Owner / verdict:** S02 — recommend; best first lifecycle slice.
- **Evidence:** AppState stores both `shouldOpenMeetingAfterFinalization` and `PendingMeetingCompletion` (`Miniti/Models/AppState.swift:517-526`). Smart Home/new/calendar paths queue the enum (`:1880-1882`, `4478-4509`), while Done/Open History sets the Boolean (`:4628-4640`). The abandoned-finalization guard clears only the Boolean (`:6002-6012`); `clearCurrentSession` likewise clears the Boolean but not the enum (`:6089-6116`). Completion gives the enum precedence and then separately handles the Boolean (`:6200-6233`). Both stopped UIs allow discard during finalization (`Miniti/Views/MeetingView.swift:2075-2077`, `2173-2185`; `MinitiMobile/Views/MeetingView_iOS.swift:27-33`, `277-295`).
- **Current complexity / invalid states:** Two independent terminal commands can coexist. A queued return/start command can survive discard or meeting replacement because session clearing never resets the enum, allowing a later finalization to consume stale intent.
- **Proposed representation:** One `PostFinalizationIntent` with `.none`, `.returnHome`, `.openSavedMeeting`, `.startUnscheduled`, and `.startCalendar(event)`. Consume it into a local value exactly once, reset it on every session-clear/abandonment path, and retain `pendingOpenSavedMeetingID` only as the separate navigation mailbox.
- **Smallest credible scope:** `AppState.swift`, lifecycle tests in `AppStateComputationTests.swift`, and lifecycle documentation. Preserve the existing public methods and durable save fence; no view API or persisted-data migration.
- **Risks / migration:** Consume before `goHome()` resets session state; do not navigate before durability; preserve calendar payloads and each Smart-meeting path.
- **Validation:** Existing deletion/save-fence tests are at `MinitiTests/AppStateComputationTests.swift:1701-1785`. Add execute-once, discard/reset, mutual-exclusion, and meeting-A-intent-never-runs-for-B tests. Later run both test bundles/builds and manually exercise Done/Open History, Smart End, unscheduled/calendar handoff, and discard during transcript finalization on both platforms, including BBC audio, iOS background and macOS Command-Q durability.
- **Confidence:** high.
- **Roadmap status:** new; not explicitly planned.

- **Owner / verdict:** S02 — recommend after F02.1.
- **Evidence:** `isRecording`, `isStartingMeeting`, `isResumingRecording`, `isFinalizingMeeting`, and free-form status are independently mutable (`Miniti/Models/AppState.swift:505-515`). ### F06.1 Synchronize the Deepgram send gate

- **Owner / verdict:** S06 — recommend.
- **Evidence:** `DeepgramService` uses independently mutable `nonisolated(unsafe)` send mirrors (`Miniti/Services/DeepgramService.swift:213-216`) and unsafe audio counters (`:328-333`). Main-actor connection paths write them separately (`:393-395`, `444`, `475-476`, `921-923`), while audio callbacks read/mutate them and URLSession completions mutate errors (`:514-535`). AppState deliberately calls `sendAudio` directly from the capture callback (`Miniti/Models/AppState.swift:5738-5740`).
- **Current complexity / invalid states:** Swift checking is suppressed without synchronization. Task presence, connectedness and counters can race across main actor, audio callback and completion queues; correctness depends on ordering spread across several lifecycle paths.
- **Proposed representation:** A small lock-protected `AudioSendGate` owning the active task plus send counters. Task presence is send-enabled state, removing `_sendConnected`. Snapshot the task/update counters under lock, never hold the lock across `send`, and retain user-visible connection state on the main actor.
- **Smallest credible scope:** `DeepgramService.swift` only; no AppState API change. Route connect/open/disconnect/send/heartbeat diagnostic reads through the gate while preserving the no-main-actor-task-per-buffer hot path.
- **Risks / migration:** Preserve current counter reset/log and five-consecutive-failure semantics; avoid lock contention/reentrancy around URLSession; validate Sendable behavior.
- **Validation:** Parsing tests do not exercise send concurrency (`MinitiTests/DeepgramParsingTests.swift:24-153`, `294-444`). Add gate lifecycle, concurrent accounting and stale-task-after-clear tests. Later run both bundles/builds and manually exercise BBC audio, pause/restart, Bluetooth recovery, forced reconnect and Stop with sends in flight on both platforms.
- **Confidence:** high.
- **Roadmap status:** new, but it must preserve the shipped no-task-per-buffer and reconnect-generation guardrails.

### F06.2 Publish one parsed transcript frame atomically

- **Owner / verdict:** S06 — recommend.
- **Evidence:** Ordered parsing already produces one `ProcessedTranscript` containing update, segments and next segmentation state (`Miniti/Services/DeepgramService.swift:539-552`), but applies it through two published properties in sequence (`:747-750`). AppState uses two subscriptions (`Miniti/Models/AppState.swift:1498-1513`) and implicitly relies on assignment order. `sourceLookup` couples parsing to `AudioCaptureService.AudioSource` (`DeepgramService.swift:227-230`, `578-585`, `615-619`, `648-657`), yet every production assignment sets it to nil (`AppState.swift:5713-5726`) and repository-wide search finds no non-nil assignment. Active mic attribution comes from `channel_index` (`DeepgramService.swift:638-647`).
- **Current complexity / invalid states:** A response transiently exposes new segments with the prior transcript update. Two Combine streams must remain ordered. Dead source attribution expands the parser contract, diagnostics and capture-service coupling without reachable behavior.
- **Proposed representation:** Publish one `TranscriptFrame` containing update and segments; consume it in one AppState sink, explicitly applying segment handling before update handling. Preserve segmentation state inside the ordered parser. The unreachable `sourceLookup` branch is opportunistic same-file cleanup, not the structural justification.
- **Smallest credible scope:** `DeepgramService.swift`, the AppState subscriptions, and `DeepgramParsingTests.swift`; connection state remains separate.
- **Risks / migration:** Preserve segment-before-update semantics, final/interim clears, channel propagation, diagnostics, `speech_final || is_final`, strict receive order and generation/socket guards. Confirm mono mic-only/system-only remains unchanged.
- **Validation:** Add frame tests for interim/final/empty/ignored frames, channel propagation, consecutive segmentation state and an AppState mismatch regression. Later run both bundles/builds plus macOS dual-channel echo/order, iOS mic-only BBC and reconnect/stale-result matrices.
- **Confidence:** high.
- **Roadmap status:** new. P1.3 short-interjection/UtteranceEnd work is separate; do not mix it into this representation change.

- **Current complexity / invalid states:** Three plist literals duplicate authoritative Xcode settings and can disagree with built output; the runbook makes humans maintain values that Xcode then overrides. macOS/iOS independent versioning must remain possible.

- **Smallest credible scope:** both app plists and `RELEASE.md`; keep target-specific pbx settings/Fastlane behavior, extension matching and platform independence unchanged.
- **Risks / migration:** Custom-plus-generated Info.plist processing must be archive-verified; Sparkle reads the final bundle values, and App Store validation requires app/extension compatibility. Do not change entitlements or signing in this slice.
- **Validation:** Later build/archive both apps, inspect final `CFBundleShortVersionString`/`CFBundleVersion` for macOS app, iOS app and extension, run `scripts/release-info.sh`, Fastlane validation, Sparkle prior-version update smoke test and TestFlight upload validation. Add a static release check that plist source uses build-setting substitution and each platform's required targets agree.
- **Confidence:** high.
- **Roadmap status:** new, though P0.5 already asks for version/release-metadata consistency checks.

### F18.1 Introduce one value snapshot at the webhook boundary

## Cross-cutting patterns

1. **Replace parallel optionals/booleans with discriminated values only where combinations are illegal.** F02.1/F02.2, F09.1, F13.1 and F15.1 each remove an evidenced contradictory state; F17.1 instead derives one effective projection from intentionally separate inputs. 2. **Snapshot identity and revision at asynchronous boundaries.** F03.1, F07.1, F10.1, F16.1, F18.1 and F19.1 prevent mutable AppState/SwiftData/UI values from being re-read after a task, callback or delivery boundary.
3. **Serialize recovery/startup as transactions, not collections of timers/tasks.** F04.1/F04.2, F05.1/F05.2, F06.1 and F16.2 define one owner, generation and commit/revalidation point while retaining distinct watchdog policies.
4. **Project canonical semantics once for every consumer.** F08.1/F08.2, F10.2, F14.1, F19.1 and F21.1 address cross-platform or live/saved drift without merging the native presentation surfaces themselves.
5. **Resolve platform policy at the boundary that has the information.** Capture topology, coached-speaker identity, managed access, typography/motion and release versions belong at their platform/configuration boundary (F04.1, F08.1, F17.1, F21.2, F23.1), not inside generic algorithms.
6. **Test pure transitions in both shared host bundles.** New values should expose deterministic transition/projection tests first, followed by targeted integration/manual matrices; no recommendation depends on a speculative generic framework.
7. **Give operational instructions one canonical owner.** F30.1 applies the same single-source principle to agent-facing release/version contracts; hidden helper documents must route to, not fork, build/release truth.

## UI and UX regression assessment

Several recommendations are UI/UX-sensitive even though most are structural. They must not be implemented as one broad refactor.

### Highest visible-regression risk

- **F21.2 typography/Dynamic Type:** text may reflow, truncate, change selection/trim heights, or expose layout assumptions at accessibility sizes.
- **F21.1 palette ownership:** correcting stale roles can visibly change MEDDPICC, speaker and Live Activity colors or contrast.
- **F02.2 lifecycle phase:** an incorrect transition/projection could show the wrong recording, paused, finalizing or stopped surface and alter control availability.
- **F07.2 insight lanes:** loading indicators, refresh cadence and result appearance timing could drift.
- **F13.1/F15.1 navigation:** back/forward history, meeting selection, Settings restoration, repeated search-result scrolling and keyboard behavior could regress.
- **F08.1/F08.2 Coaching:** iOS intentionally changes misleading unknown-subject `You: 0%` output to unavailable; speaker aggregation and stable row identity must remain consistent.
- **F19.1 Markdown export:** consolidation can change headings, ordering, Notes and feature-section inclusion unless golden compatibility decisions are made first.

### Intended user-visible corrections

- Stale Smart Meeting notifications no longer end or replace a newer meeting.
- Disabling automation during a countdown cancels the pending automatic action.
- Store initialization failure presents a recoverable error rather than terminating the app.
- Transcript punctuation/grouping becomes consistent across live, saved and exported text.
- Selectable transcript/insight prose responds correctly to Dynamic Type.
- Proven stale palette roles converge on the canonical colors.
- Webhook/Markdown surfaces may include sections that were previously omitted on one source path.

Audio, persistence, entitlement and transcript-publication changes are less visually obvious but have higher functional consequences if wrong: recording startup/source selection, durability, subscription gates or live transcript freshness can regress.

### Rollout guardrails

1. Implement one narrow finding per change; do not bundle broad lifecycle, lane, palette, typography or navigation migrations.
2. Add pure regression tests before migrating UI consumers.
3. Preserve compatibility projections/adapters during lifecycle, navigation and persisted-model transitions.
4. Use screenshot/manual comparison for palette, typography, Coaching, Settings, History and Live Activity.
5. Run real-device audio, background, subscription and notification tests for affected findings.
6. Treat “no visible change except in the broken/stale scenario” as the acceptance target for the high-priority correctness fixes.
