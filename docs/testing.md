# Testing

Two XCTest targets share the same 18 test files in `MinitiTests/`:

- `MinitiTests` — tests the macOS `Miniti` host app
- `MinitiMobileTests` — tests the iOS `MinitiMobile` host app. It runs fewer cases because audio-source ring/RMS, export helpers, the system-callback watchdog, native long-transcript layout, and main-window navigation tests are macOS-only, partly offset by iOS-only Live Activity privacy and StoreKit-state tests

Covers JSON decoding, data models, pure computation, payload construction, the persistence policy with injected failures, the managed API transport with a stubbed `URLSession`, and the post-audio meeting journeys at the `AppState` level. No XCUITest target: view wiring is covered by the launch smoke gate (`scripts/screenshots/smoke.sh`) and the manual matrices below. Audio capture and the live Deepgram socket stay manual.

## Running tests

Use the fastlane lanes. "The test runner hung before establishing connection" on macOS (seen 2026-10-15 with a direct `xcodebuild test -only-testing:` run and 2026-10-21 with `fastlane mac test` itself) is a Keychain permission dialog: `AppState.init` reads the managed credential through `SecItemCopyMatching` on the main thread, the Debug-signed test host is not the app that wrote the item, and macOS puts up "miniti wants to use your confidential information stored in the keychain", which blocks the host before it can connect to XCTest. Sampling the host (`sample <pid>`) shows the main thread inside `KeychainClientAuthStore.load()`. Click **Always Allow** on that dialog once and the lanes run. It used to come back whenever the release app re-created the item (every token refresh deleted and re-added it, and a Sparkle update did on 2026-10-21); since 3.3.0 `KeychainSlot` updates the item in place, so the access list, and the Always Allow, survive. The data protection keychain (`kSecUseDataProtectionKeychain`), which has no per-app access list, is not an option on macOS: neither the Developer ID release build nor the Debug host carries the `com.apple.application-identifier` entitlement it needs, so writes there fail with -34018 (the 3.2.1 regression, postmortem in `docs/distribution.md`). `KeychainSlot` tries it first and falls back to the login keychain; `ClientAuthTests` covers both with `FakeKeychain`. The macOS host app shares the Mac's own Keychain, so a test that constructs `AppState()` may find it enrolled. It shares the installed app's settings too (the Debug host is sandboxed, same container), so `TestRunSetup`, the bundles' principal class, captures the whole defaults domain before the first test and puts it back after the last one; before 2026-10-21 it protected five engine keys only, and `CloudSyncAppStateTests` left the person's cloud switch off.


GitHub Actions (`.github/workflows/tests.yml`, `macos-26` runners, Xcode 26.6) runs both bundles on every push. The runner lists an input device that delivers nothing and builds the host unsigned, and the shell's `CI` variables never reach the host process, so the skips ask the system (`TestHost` in `TestSupport.swift`): `MeetingHandoffTests` that drive the real capture pipeline skip unless the host has microphone authorization (`requireMicrophone`), and the notification-category test skips when the host's notification center returns no categories right after registering (the runner's host has no team signature; an ad-hoc signature validates, so the signature itself is no signal); everything else must pass. Until 2026-10-21 the workflow's success check matched any suite line with 0 failures, so a run with 15 failing tests (2026-10-19, 3.2.0) showed green; it now fails on xcodebuild's own exit status and reads the bundle total. The local lanes remain the release gate (`RELEASE.md` step 2), because the runner cannot run the hardware tests and its Swift 6.3.3 compiler has crashed once on an unchanged file (2026-10-21).

- Run macOS tests: `fastlane mac test` (or `xcodebuild test -scheme Miniti -destination 'platform=macOS' -derivedDataPath DerivedDataLocal -only-testing:MinitiTests`)
- Run iOS tests: `fastlane ios test` (or `xcodebuild test -scheme MinitiMobile -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath DerivedDataLocal -only-testing:MinitiMobileTests`)

Two destination gotchas on the iOS side, both of which surface as "Unable to find a device matching the provided destination specifier": pin `OS=` to the version of the *installed simulator runtime*, not the SDK version (`xcodebuild -showsdks` can report a point release ahead of any runtime you have), and prefer `id=<udid>` over `name=` when several simulators share a name. `xcodebuild -showdestinations -scheme MinitiMobile` lists exactly what resolves. `fastlane ios test` handles both by resolving a UDID itself — see [../fastlane/RUNBOOK.md](../fastlane/RUNBOOK.md).

## Launch smoke gate

`scripts/screenshots/smoke.sh [ios|mac|all]` builds the Debug apps and runs every screenshot scene (Home, recording in each insights mode, Coaching focus and stats, History, saved meeting, Settings, Account & Plan, the P0.2 recovery screen, the P0.3 banner). A scene passes only if the macOS app opens its window, renders, writes its PNG, and exits 0, or the iOS app reaches first layout and writes `<container>/tmp/miniti-screenshot-ready-<scene>` (a crash behind a blank capture fails). It is the launch/Home/Settings/history-navigation smoke the roadmap asked for, without an XCUITest target; it cannot exercise record → stop (covered at the `AppState` level in `MeetingJourneyTests`) or trackpad gestures (manual). Quit the installed Miniti first on macOS.

- **Manual-only hardware boundaries (P0.6)**: microphone and system-audio capture, Bluetooth route changes, echo suppression between mic and system channels, the live Deepgram WebSocket (connect, reconnect ladder, CloseStream), iOS background audio and the Live Activity, macOS trackpad back/forward gestures, and the floating recording surface. - **Store recovery drill (P0.2)**: with the installed app quit, use a scratch path the sandboxed macOS app can write, `D=~/Library/Containers/com.miniti.app/Data/tmp`, then `head -c 4096 /dev/urandom > $D/bad.store` and launch the Debug build with `-MinitiStoreURL $D/bad.store` (macOS: `open -n DerivedDataLocal/Build/Products/Debug/miniti.app --args -MinitiStoreURL $D/bad.store`; iOS simulator apps are not sandboxed the same way, so `xcrun simctl launch <udid> com.miniti.mobile -MinitiStoreURL /tmp/bad.store` works). A path outside the container such as `/tmp/x.store` makes the app report `category=io` (sandbox denial), which is itself a useful check. Expect the "can't open your meetings" screen with the corruption copy, a working "export diagnostics", "show database folder" (macOS), and "get help"; "try again" must stay on the screen. ## Cross-platform test files

All 18 test files compile for both macOS and iOS via conditional imports (`#if IOS_TEST_TARGET` → `@testable import MinitiMobile`, else `@testable import miniti`). The `IOS_TEST_TARGET` flag is set in `MinitiMobileTests` build settings via `SWIFT_ACTIVE_COMPILATION_CONDITIONS`. macOS-only tests (markdown export helpers) are guarded with `#if os(macOS)`. `ColorPaletteTests` uses a cross-platform `colorComponents()` helper (`NSColor` on macOS, `UIColor` on iOS).

## Access control for testing

Pure helper functions and data-only structs that need direct testing are `internal` (not `private`) so `@testable import` can reach them. These include:

- `AppState.isNewer`, `AppState.sanitizeFilename`, `AppState.parseMeetingTitle`, `AppState.isTransientInsightsError`, `AppState.shouldFireLiveInsightCadence` (+ `LiveInsightCadencePolicy`), `AppState.buildSegmentSyncPlan` (+ snapshot/plan structs), `AppState.mergeStoppedInterimTranscript`, `AppState.recoverySeverity`, `AppState.transcriptText`, `AppState.tailTranscriptSegments`, `AppState.evaluateAutoStop` (+ `AutoStopDecision`), `AppState.evaluateTranscriptHealth` (+ `TranscriptHealthAction`), `AppState.isLikelyMicEcho` (+ `EchoComparisonSegment`), `AppState.AutoStopReason`, `AppState.noteMeetingDeleted` / `isMeetingDeleted`
- `MainNavigationHistory` and `MainWindowNavigationSwipePolicy` (macOS only)
- `TrainingStatsOverview.chartPoints`, `TrainingStatsOverview.chartAxisMeetingIndices`, and `CoachingChartPoint`
- `DeepgramService.segmentBySpeaker` (+ `SegmentationState` struct and channel propagation), `DeepgramService.findDominantSpeaker`, `DeepgramService.PendingSpeakerEvidence`, `DeepgramResponse`
- `InsightsService.tokenize/countPhraseOccurrences/computeLongestMonologue`, `LiveInsightsResponse`, `InsightsResponse`, `OpenAIResponse/OpenAIErrorResponse`
- `MinitiAPIService.decodeFlexibleDate/timestampToDate`

Pure static functions on `@MainActor AppState` are marked `nonisolated static` so tests can call them without async context. Instance methods that previously had the same name delegate to the static versions to avoid breaking existing call sites.
