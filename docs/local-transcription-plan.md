## Design

**Where recognition runs.** `OnDeviceTranscriptionService` downloads and preloads one `SharedNemotronMultilingualModels` per model family (latin or multilingual, chosen from the meeting language). `beginSession` creates one `StreamingNemotronMultilingualAsrManager` per capture source (macOS: microphone and system; iOS: microphone) from the shared weights, applies personal dictionary and calendar keyterms as vocabulary biasing, and starts one worker task per source that drains an `AsyncStream` of 16 kHz float samples. The audio callback that already feeds the diarizer and Deepgram now reaches `DeepgramService.sendAudio`, which hands PCM16 to the local session (`splitPCM16` de-interleaves dual capture) instead of a socket.

**Words and utterances.** After each 1120 ms chunk the worker reads the manager's accumulated token timings and feeds the new ones to a `LocalUtteranceAssembler`. A token whose SentencePiece piece starts with `▁` begins a word; the rest extend the current word, punctuation included. The assembler emits a final when the current word ends with sentence punctuation, when the decoded horizon is 1 s past the last token, or when the pending utterance reaches 12 s; otherwise it emits an interim with the pending words. Timings are seconds from the session's first sample, exactly how Deepgram's socket-relative timestamps behave, so `deepgramTimelineOffset`, the diarizer's `markSocketStart`, and the chronological insertion logic are unchanged.

**Into the existing pipeline.** `DeepgramService.connectLocal` sets up the same per-connection state as `connect` (identity allocation, segmentation state, mono/multichannel source attribution, on-device speaker timeline) and marks the service connected without opening a socket. Each assembler event becomes a `DeepgramResponse` (channel index 0 mic, 1 system in dual capture) and runs through `processTranscriptResponse`, the body that the JSON path also calls, so speaker mapping from the on-device timeline, speaker promotion, echo reconciliation, corrections, and persistence are untouched. Without on-device speaker separation every local word carries provider speaker 0 for its source: "You" on the mic and one remote speaker on the system channel. The setting copy says to turn speaker separation on as well.

**Session end.** `gracefulDisconnect` finishes the local session (the manager's `finish` flushes the last tokens, the assembler flushes its pending words) and waits up to 0.8 s for the last final, as it does for Deepgram's CloseStream. A transcript stall restarts the local session through the same watchdog path that reconnects Deepgram, preserving speaker identities.

**No silent upload.** While a session is local there is no WebSocket task, so `sendAudio` cannot reach Deepgram. The engine is chosen once at start. A model that is already on disk but still loading (the first seconds after launch, or after a language change) counts as available: the start waits up to 30 s for it. A model that is missing or still downloading does not: if "use Deepgram for that meeting" is off, the start is refused with a visible message. Found by the handoff tests on 2026-10-09 once Ian's own install had the setting on: a start right after launch was refused while the model loaded. Mid-meeting engine failure logs once, stops feeding, and the transcript stops; the recording continues.

**Tiers and metering.** Managed mode does not request a Deepgram session for a local meeting, so no minutes are reported or counted. BYOK needs no Deepgram key when the model is ready. The managed limit still gates starting a recording because insights go through the same allowance; revisit when local insights exist.

**Languages.** From the measured WER: English, Spanish, French, German, Portuguese, Italian run locally (latin family); Dutch and Russian run locally and are labelled experimental (multilingual family); Greek, Polish, Swedish stay on Deepgram and the setting copy says so.

## Non-negotiables carried over

- Never delete the Deepgram path. Every failure to prepare, start, or run the local engine either keeps Deepgram (only when the user allowed fallback for that meeting) or stops transcription visibly.
- No transcript or audio leaves the device for transcription when a session is local. The model download is the only new network call, and it is weights only.
- `../miniti-linux` keeps Deepgram until the ONNX build is evaluated there; tracked in its PLAN.md.
