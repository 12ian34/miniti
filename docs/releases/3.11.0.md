# 3.11.0 release plan

**Status, 2026-11-16: building.** Ian said go the same day. Canonical device records are active in production after D2, completed with Ian's go on 2026-11-16; the independent D3 account lookup package and its public copy are live; the reviewed ownership backend is deployed after D4 in `device` mode, with the subscription switch still pending. Final code review and focused blocker rechecks are complete. Local switch and native compatibility exercises pass; owner acceptance, provider checks and rollout gates remain open. [Progress](#progress) says where the build is. The 3.11.0 apps are not versioned or published. Mac 3.10.0 build 166 is public; iOS 3.10.0 build 166 is in App Review with automatic release and 3.9.0 is still the App Store version; Linux 0.7.2 is public on its own line. The [roadmap](../roadmap.md) stays the sole priority index. This file is the canonical 3.11.0 checklist and resume point. [Account ownership, the simple version](../plans/account-ownership-simple.md) is the build design: storage keys, functions, server answers, app screens and wording, tests, and the steps of the switch. The [planning audit](3.11.0-planning-audit.md) owns findings, dimension coverage, the surface register and the implementation-finding queue.

**How this plan got here, all on 2026-11-16.** A first plan kept the service live while ownership changed underneath it. Astra reviewed it twice and it grew to 133 to 226 hours. Ian asked for the same outcomes more simply for a service with few users, and adopted the simple version: a short maintenance pause in place of the live changeover, one minutes counter per account per billing period in place of a usage ledger, and an hourly check against Polar and Apple in place of ordering their events. Astra reviewed that design twice more, then reviewed this file, the design note, the audit and the roadmap as a set: device-record work can start, and six contract fixes were needed before the ownership code. All fixes are in the design note under [Astra's review](../plans/account-ownership-simple.md#astras-review). Ian also decided the same evening to start work that day and not wait a day after the 3.10.0 release; nothing in the plan depended on that wait. The earlier plan is kept as a record in the [cutover plan](../plans/account-ownership-cutover.md) and is superseded.

Done during planning, each with Ian's go-ahead: a read-only export of production subscriptions and one App Store Server API read; a private copy of production device records and a local rehearsal of the device-record merge; two Linux issues.

## Selected scope

Decided by Ian on 2026-11-16. Architecture ids (B0 to B3) and package ids (AO1 to AO4) are unchanged.

| Package | Architecture stage | Outcome |
|---|---|---|
| AO1 | B0 | One record per device. First, on its own, as soon as possible |
| AO2 | B1 | A subscription belongs to one account, fixed at first bind. Signing out or changing devices no longer moves or removes Pro. On iPhone and iPad, Pro comes only from the server |
| AO3 | B2, B3, lookups | Minutes belong to the account, counted per billing period. An emptied account stays and gets one email if it is paid. 100 free docs lookups per account per month |
| AO4 | compatibility and publication | What the apps are told, the refusal for old apps, the app's wording, rehearsal, release, the switch |
| FX | field fixes | Small client-only fixes accepted until client freeze (F-1); the 3.10.0 field check (FX0) |
| LX | Linux tracking | Issues in the public Linux repository. Nothing is built |

### Moved to 3.12.0 (Ian, 2026-11-16)

Meeting provenance and copies (B4), account connections (B5), CK1 durable checkpoints, HP1 History and long-session budgets, RG1 registration and registry. Their slices and acceptance stay in the [3.10.0 checklist](3.10.0.md#work-packages-and-slices) until a 3.12.0 checklist exists. Consequences for 3.11.0: no SwiftData schema change, no connection or copy UI, and the account-change wording says that connections and meetings stay with the device.

### Not in 3.11.0

Everything the 3.10.0 checklist excluded, plus: account merging, self-service subscription transfer, any Linux build, shutting off the old shared key (a purchase needs an account, so the shared key cannot own one; the wider shut-off stays a [roadmap candidate](../roadmap.md#candidates-not-active-release-commitments)), a cleanup job for empty accounts, `appAccountToken` for new iOS purchases, raising the app minimum version. The two older incident-email defects deferred from 3.10.0 (N30, N31) are backend only and need no app release; the [roadmap](../roadmap.md#operator-reporting-backend-only) carries them, with the minimum-version question under its candidates.
