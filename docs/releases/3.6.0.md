1. **Backend:** obtain deployment authorization, run backend validation, deploy alert clarity when ready, independently of the app schedule. Only genuinely required additive client contracts must precede their app consumers. Record revision and deployment. Inspect a normal hourly run and last-notified evidence; do not force production email or clear state to manufacture a pass. Preserve existing UptimeRobot coverage and provider checks.
2. **Shared contract/docs:** update current-behavior reference docs, operations, user-facing docs and concise per-platform release notes only to describe built behavior. Add the Linux tracking commit/issue for applicable payload/UX changes. The roadmap remains the sole priority index.
3. **Build metadata:** choose a build greater than the latest uploaded build at release time; do not assume 144 is free. Set 3.6.0 consistently using the release runbook. Confirm the supported upload Xcode version before iOS packaging.
4. **Release candidates:** build signed/notarized Mac and iOS candidates and complete the device checks above against those candidates. If a fix changes tested behavior, rerun affected checks and required suites on the final combined tree.
5. **macOS:** with release authorization, publish the DMG/appcast/site; verify live bytes, signature/notarization and Sparkle update from the shipped version. Record release asset, build, time and checks.
6. **iOS:** with submission authorization, upload and submit. Record upload, review and App Store availability separately. Update `IOS_LATEST_VERSION` only after availability is confirmed. Never change Linux version constants as part of this release.
7. **Observe and close:** verify ordinary sync/diagnostics and hourly alert evidence, distinguish failures from historical reports, and record unresolved checks or explicit waivers. Close each complete plan only with its own implementation/test/deployment evidence; move durable gotchas into reference docs.

Rollback is per component. Preserve notification identities and pending work; do not reset evaluator history and resend old alerts. Preserve completion-marker/outbox data and cloud exclusions. If a downgraded binary would discard new successors or replay handoffs, use a forward patch instead. No rollback may restore trimmed content or remove account fences.
