## Shared boundaries

- One owner controls recording start, reconnect, restoration and Stop. Late work from a prior recording/account cannot apply credentials, transcript results, labels or usage to a new owner.
- Connection restored, transcript resumed and speaker separation restored remain distinct observations. None proves that missing audio was recovered. No buffering/replay is added.
- Default-off local speakers and opt-in Your voice remain unchanged. Local-only/private transcription never gains a cloud fallback from this work. M1 default-on research stays separate.
- Managed Deepgram usage remains distinct from the shipped local-duration queue. BYOK emits no usage reports; diagnostic consent never gates accounting. Preserve private-mode export permissions and current allowances.
- Account access does not migrate Pro, usage, meeting or integration ownership. Test that existing accounts and recordings retain their current identity through the changes.
- Additive APIs must support installed Apple and Linux clients. Before any wire change, record exact request/response/error fixtures and Linux tracking in its PLAN.md. Linux has a separate release line.
- Diagnostic fields remain allow-listed and content-free. Device labels, keys, emails, audio, transcripts and link tokens must not enter diagnostic payloads.

## Failure, privacy and recovery requirements

- Accounting failures do not block local save/final words. Retry transient transport/server errors through the bounded queue; terminal v2 owner/expiry/validation errors count as dropped coverage. Never retry a pending charge using a different account.
- Sign-out remains possible offline. Attempt pending usage delivery while authorized; retain for the same owner or quarantine/drop on account replacement. This release does not solve the deferred device-to-account historical usage migration.
- Recovery failure leaves clear unavailable speaker state, retained transcript and existing Stop behavior. Silence never causes a second speaker-specific reconnect.
- Failed Watch imports retain audio until the existing successful receipt/save contract allows deletion. Failed summary generation resumes from the saved transcript. Never delete a queue item just to clear a spinner.
- A claimed generic sign-in/confirmation link stays consumed if a later side effect fails; the user can request a fresh link. Do not reuse link tokens or weaken device-enrollment proof to make retries easier.
- Session/recording IDs and editable labels add no meeting content to telemetry. Labels are personal account metadata and must not enter diagnostics. Review privacy/docs retention wording against the implemented v2 queue/receipt rules internally, with no special App Review outreach.
