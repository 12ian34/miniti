# Miniti

Released on Mac, 2026-11-09: 3.8.0 build 164 is public through the verified DMG and Sparkle feed. iOS build 164 is available in internal TestFlight and submitted as WAITING_FOR_REVIEW with automatic release after approval; 3.7.0 remains the App Store version. Full Mac/iOS suites, all 31 iPhone journeys, remote Apple CI and signed-package checks pass. Ian completed app QA and App Privacy. The backend, Linux 0.7.2, website and public docs are deployed. Unitemised specialist device checks remain evidence limitations, not claimed passes.

macOS + iOS meeting assistant app built with SwiftUI + SwiftData. Records mic + system audio (macOS) or mic-only (iOS), streams to Deepgram for live transcription with speaker diarization, generates AI insights via OpenAI. Three tiers: free managed (500 min/month), pro managed ($5/month, 5000 min/month), or BYOK (own API keys, unlimited). Pro purchase rail is platform-specific: Polar.sh on macOS and StoreKit auto-renewable subscription on iOS.

This file is the canonical entry point for AI coding agents working on Miniti. It points at focused docs for each concern. Don't dump new long-form prose here — add it to the right `docs/*.md` instead.

## Tech stack

- SwiftUI + SwiftData (macOS 14.2+ / iOS 17+)
- Xcode 27.1 release toolchain, Swift 6 concurrency
- Deepgram Nova-3 streaming (WebSocket)
- Optional on-device speaker diarization: NVIDIA Nemotron-3-Diarization via the FluidAudio Swift package (Core ML, Apple silicon), default off, replaces Deepgram's diarizer per word when active. Optional on-device transcription (2.12.0, macOS, default off): NVIDIA Nemotron 3.5 ASR Streaming Multilingual 0.6B through the same package, downloaded on demand (not bundled), replaces the Deepgram socket for the session when active. The 190 MB model is bundled: `scripts/fetch-nemotron-model.sh` (pinned, checksummed) fills the gitignored `Miniti/Resources/NemotronDiarizer/` as the first build phase of both app targets
- TypeSafe Jev (`jev-1.13.0`) through the managed `/api/classify` proxy for attendee speaker naming and the sales nudge, opt-in (`jevClassifierEnabled`, default off), never generates text; GPT and the phrase heuristics remain the fallback
- OpenAI insights: By default, managed full and incremental `standard`, `meddpicc`, `questions`, `template`, `docs` and `investigation` requests use pinned `gpt-5.4-mini-2026-03-17`; `speaker_names`, `catchup`, `docs_topics` and `template_draft` move to `gpt-6-luna` with reasoning `none` in the deployed 3.6.0 backend, activated on 2026-11-01. For those four tasks, only `INSIGHTS_LIGHTWEIGHT_LUNA=on` enables Luna; unset, blank, `off` or unrecognized values use pinned GPT-5.4 mini with low reasoning in the deployed 3.7.0 backend. Managed `standard` full/incremental summaries independently opt into Luna none with `INSIGHTS_STANDARD_LUNA=on`; unset/off/invalid retains GPT-5.4 mini low. See [bounded migration](docs/plans/lightweight-luna.md); both Luna groups are enabled in production from 2026-11-01 after baseline observation and synthetic production API verification. `INSIGHTS_INCREMENTAL_QUALITY_MODEL=off` takes precedence over standard Luna and selects GPT-5.4 mini with low reasoning for quality-mode incremental requests in 3.7.0. 3.7.0 BYOK uses `gpt-6-luna` with reasoning `none` for summaries/helpers and pinned `gpt-5.4-mini-2026-03-17` with `low` for specialist insights. Mac 3.8.0 build 164 is released; iOS build 164 is waiting for App Review, with 3.7.0 build 149 still available on the App Store. Older BYOK clients still require the retirement update.
- Vercel + Upstash Redis backend (`miniti-api`)
- Sparkle 2.9.5 for macOS auto-update; StoreKit 2 + Polar.sh for purchase rails
- GitHub release assets for current DMGs, with Netlify download redirects; legacy downloads may remain in Netlify Blobs

## Non-negotiable conventions

- **Design tokens**: all colors route through `ColorPalette` in [Miniti/Models/ColorPalette.swift](Miniti/Models/ColorPalette.swift). Never hardcode hex literals in view code. Meaningful hints/actions meet the ordinary-text contrast target; placeholders use readable text and solid recording fills pair with `ColorPalette.OnAccent.recording`. See [design.md](design.md) for the full spec (typography, spacing, components, contrast).
- **Design system**: shared spacing, radius, control, motion, opacity, semantic control roles, navigation copy, and content-accent contracts live in `MinitiDesignSystem`; compact controls use `MinitiControlLabel`, while mutually exclusive views use the lowercase neutral `MinitiTabLabel` / `MinitiTabStripSurface` pair. Sales insight identity, order, titles, colours and live/saved value projection use `SalesInsightField` and `SalesInsightSectionList`; standard sections use `StandardInsightSection` and `StandardInsightSectionList` for typed content, order, names and accents, preserving each screen’s existing field coverage and empty-summary policy. Preserve per-platform section layouts and template descriptors. Standard insight lists use `InsightList`, one selectable surface per list with measured marker indents and shared reading spacing. Mac live and saved discussion keep numbering. Saved iOS actions have no view-local completion state; CRM task selection and Markdown exports keep their own contracts. On iOS, `MinitiMeetingSectionPicker` owns the shared live/saved transcript, insights and notes strip; each screen retains its own selection and content. Equal-width segmented strips set `fillsAvailableWidth` so every label surface and hit target occupies its full segment. Shared control/tab labels and disclosure rows reserve platform minimum targets in normal layout, retaining compact visual chrome; constrained parents can still cause overflow, so audit neighbouring target frames before release. Metric-help/close and question/docs copy controls use the same target allocation and explicit accessibility names; copy actions retain native keyboard-focus eligibility. Coaching metric taxonomy lives in `ColorPalette.Coaching` and must stay consistent across live, history, overview, examples, and charts without reusing CTA/status colors. Coaching history sort headers use shared minimum targets and full accessible sort names; on iOS, aligned 44-point metric columns and a 70-point meeting minimum form a 328-point table with horizontal scrolling below that width. The Coaching overview separates focus/trends, aggregate stats, and meeting history into lowercase `focus` / `stats` / `history` tabs; its stats include all six Coaching metrics, keep each metric plus unit on one line, show the metric explanation inline below rather than behind an info icon, and use success/error/neutral status colours for semantically good/bad/neutral changes. Historical metrics use six separate cards directly below the uninterrupted comparison table; each chart keeps its own metric scale, numeric y-axis, and adaptive meeting-sequence x-axis with plain numeric ticks under a centred `meeting` label rather than combining incompatible units or using elapsed calendar time. `CoachingLayout` owns its 720pt reading/stats-column, platform chart height, and 480pt compact-column bounds, `CoachingTypography` owns its desktop reading-size step, trend sections sit directly on the background with `MinitiFadingDivider`, grounded examples alone retain content-sized hover cards without disclosure chevrons, copy does not truncate, and grounded examples keep the label/quote together at left with a right-aligned meeting title over a date-only line. macOS back/forward swipe thresholds and the neutral edge progress cue use the shared `NavigationGesture` contract. Preserve native `Button` / `Menu` ownership of actions, focus, disabled state, shortcuts, and accessibility. The Mac live-notes pane keeps a 100-point minimum including its header, so resizing leaves room for editing. Migrated help/copy and live/saved insight Update actions use the shared minimum-target allocation; platform keyboard and adaptive-layout acceptance remain in the release checklist. Do not pass arbitrary feature colors into ordinary controls or fork shared component measurements inside feature views.
- **Typography**: Apple system font for readable prose, controls, and primary Home / Coaching / History navigation. The `miniti` lockup retains the original monospaced identity; timers/counters use monospaced digits. `ReadingMetrics` resolves transcript/insight/notes sizes from InterfaceScale, plus unshifted system Dynamic Type on iOS, and supplies final point sizes to SwiftUI and attributed text. Use `minitiInterfaceScale` at roots; never apply automatic UIKit scaling to already-resolved attributed fonts. Transcript and insight prose share the same platform-specific size at every interface scale. Shared reading metrics resolve Mac from InterfaceScale and iOS from InterfaceScale plus the live hosting-view Dynamic Type environment; do not read the system text size from the App root. iOS system-text-style controls also receive the live category plus the existing InterfaceScale shift; their app-wide accessibility layout matrix remains a UI1/UI3 gate. Dark mode only; main, Settings and Debug Log Mac roots prefer dark appearance without forcing the application-wide appearance or system menu bar.
- **Accessibility + adaptation**: app-authored animations must respect Reduce Motion. iPhone keeps the compact tab bar; regular-width iPad uses adaptive sidebar navigation. New visual materials are limited to functional system surfaces and must preserve contrast.
- **State**: `AppState` is the single source of truth, injected via `@EnvironmentObject`. Transient high-frequency UI signals live in `AudioLevelsState` / `TranscriptRuntimeState` to avoid invalidating the whole `AppState` on every sample. `HomeSetupState` owns setup presentation preferences and permission evidence so setup-only animations do not invalidate history.
- **Platform guards**: keep `#if os()` localized. Most branching is in `AppState.swift`; each target compiles its own `AudioCaptureService` with the same class name + public interface.
- **Model context wiring**: `appState.modelContext` must be set from `@Environment(\.modelContext)` in the first view that appears (`MainWindow.swift` on macOS, `MainTabView.swift` on iOS). Without it, `saveCurrentMeetingIfNeeded()` silently no-ops.
- **Hot-path performance**: never `.filter` `@Published` arrays in callbacks that fire on every transcript finalize (grows unboundedly). Iterate `.reversed()` and break on window expiry. See [docs/reference/patterns.md](docs/reference/patterns.md) § "Performance / hot-path rules".
- **Changelog style**: compare the final candidate with the previous publicly released version, not commits or development iterations. Features first shipping here are new; omit fixes for regressions introduced and repaired entirely within this unreleased candidate. Keep iteration history in the internal release record. Public-audience prose, no code refs. Never edit old entries unless the user explicitly requests a historical correction. Release headers are date + version only; platform availability belongs in bullets, never parenthetical header status. One flat bullet list per release with `new:` / `improvement:` / `fix:` prefixes, never sub-headers like "New features" or "Experience improvements". The product name is always lowercase (miniti). Write bullets in Ian's voice: short plain sentences, specific numbers, simple verbs, no em dashes, no "not X, it's Y", no bold, no exclamation marks. Rules and examples live in the public [changelog skill](.cursor/skills/changelog/SKILL.md). Its instructions are self-contained; personal voice material remains outside this repository. The changelog file itself holds entries only, no style section.
- **Managed-mode auth is device-bound** (`Miniti/Services/ClientAuth.swift`): a per-install P-256 key (Secure Enclave when available) plus an anonymous recovery key; `MinitiAPIService.send(_:)` attaches the bearer token and an ES256 `X-Request-Proof` on writes. No shared backend secret exists in the app; never reintroduce an `X-API-Key`. Existing installs migrate silently via `/api/auth/migrate` (`AppState.ensureManagedEnrollment`). An enrolled install moves to another account with `POST /api/auth/account/attach` (`ClientAuthManager.attachToAccount`, rewrites key/account/tokens in place, never signs out); Pro sponsorship arrives as `entitlement_via_account` on `/api/usage`. The Swift prompt/vector contract is shared with `../miniti-api` (`test/fixtures/client-auth-vectors.json`) and `../miniti-linux`.
- **macOS is shipped sandboxed** — `com.apple.security.app-sandbox` + audio-input + network + user-files entitlements. Don't call `codesign --force --sign` on a bundle that has entitlements without also passing `--entitlements` (that's what caused the v1.24.0 history-wipe regression — postmortem in [docs/reference/distribution.md](docs/reference/distribution.md)). Sparkle also needs `SUEnableInstallerLauncherService = true` plus `com.miniti.app-spks` / `com.miniti.app-spki` mach lookup exceptions, or sandboxed installs fail after download with `Failed copying system domain rights: -60005`. Keep Sparkle at 2.9.3+ (currently 2.9.5): older 2.9.1 collides with the `.app` suffix in Miniti's bundle ID and can trigger a first-attempt macOS security denial. The Developer ID build carries no `com.apple.application-identifier` entitlement (no provisioning profile), so `kSecUseDataProtectionKeychain` fails with -34018 on macOS; both Keychain items go through `KeychainSlot`, which falls back to the login keychain (3.2.1 postmortem in [docs/reference/distribution.md](docs/reference/distribution.md)).

**Private-mode boundary (Ian, 2026-10-26):** configured webhook and CRM exports remain allowed. Do not turn private mode into a blanket network/export ban. 3.4.0 locks the switch during starting, recording, resuming and finalizing, and adds History/Watch permission guards. The wider AI-entry-point audit remains deferred. Do not claim that a preference toggle changes an already-running transcription engine.

## Learned user preferences (from prior Codex sessions)

- When large or Codex-authored diffs are uncommitted, the user often wants an independent second-pass review (another agent) before treating them as shippable.
- For the top-of-file changelog and App Store-style "what's new" text: keep language plain and user-facing; put technical depth elsewhere in sub-docs; order items **new → improvement → fix**; deduplicate; keep listing copy aligned with what actually shipped.
- When updating iOS release notes, double-check that bullets apply to the mobile app and are not macOS-only unless explicitly scoped.
- For UI tweaks, prefer small targeted changes over large rewrites when fixing regressions; follow explicit layout and copy instructions literally.
- The user values clear labels and keyboard hints on macOS home actions (e.g. shortcuts/settings) alongside icons when both are requested.
- Meeting utility actions such as Investigate and Catch me up use labelled neutral `MinitiControlLabel` chrome with aligned SF Symbols; do not substitute emoji or one-off button layouts.
- No em dashes anywhere in the product, not only in copy: menus, settings, errors, notifications, exports. Use commas, full stops or colons.
- Settings tabs are single words, one question per tab, grouped Setup / Meetings / Connections / Privacy / Support (Cloud is a separate Setup tab after Account since 3.0.0; API is its own tab in Connections since 3.2.1, visible to everyone with the upgrade path when Pro or cloud is missing); model choices are "Deepgram" or "This Mac" pickers, never model names in the control. Privacy and Support are separate; Help contains support/reporting; About contains version, links and acknowledgements (3.5.0).
- Account UX contract (delivered in 3.4.0): suggest optional verified email without enabling cloud or requiring Pro; keep recovery key as backup and billing/license restore separate. B6a owns state-aware labels and full recognizable email in Account. Sending U1 should group concise data flows with one Configure action per row; consent U2 keeps actions visible outside the scroll body. B6a and U1/U2 are delivered in 3.4.0 build 141; later first-use choices remain planned.
- Do not label Jev or the Nemotron models as beta. Insight menus show names only, with a settings link at the bottom, never "Name — description".
- Normal updates should not appear as home-screen banners: macOS uses Sparkle and iOS uses the App Store. Keep `/api/version` only for the minimum-version force-update gate.
